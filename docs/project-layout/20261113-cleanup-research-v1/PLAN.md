# 项目整理实施方案

日期：2026-11-13。本轮按“先调研、形成方案”交付；未提交、推送、删除、移动、归档或重建。配套[实测盘点](SURVEY.md)给出目录体积、Git 状态和统计边界。

## 结论与顺序

后续实施顺序：先完成 Git 更新和推送，再按下表确认支线去留，最后对全部文件确定清理等级和精确处置范围，交用户选择后执行。Git 整理、必要修正和验证可在已确定范围连续完成，不逐文件请示。建议主线采用 L2，废弃展示试验评估 L3，仅在用户明确放弃某支线时考虑该支线 L5。当前不承诺可释放空间：必须先完成依赖、同哈希存活件和归档验证，删除后以实际磁盘空间变化记账。

逻辑分组用于理解能力、责任和消费关系，不要求物理搬迁或拆成多个 Git 仓库。当前已经有子项目入口，本轮沿用并细分；机制路线实验属于技能研究子集，不重复计入总量。容量按[实际目录汇总](SURVEY.md)判断，不将八组当作互不重叠的物理目录。

## 一、先整理 Git，形成可追溯代码基线

当前本地 main HEAD 为 `56a9d17`，最后提交于 2026-11-08，本地 `origin/main` 指向同一提交；远端实时状态未知。本轮远程查询因本机 `127.0.0.1` 代理不可连接而失败，不能据此认定远端无变化。工作区存在大量其他成果：约 169 个已跟踪修改、9 个已跟踪删除，以及约 13,624 个未跟踪文件；数字随扫描时点可能变化。

1. 重新读取 `git status`、差异和现有任务写入范围，逐项区分源码、配置、文档、必要规则与数据、生成物、其他任务成果。不得使用 `git add .`，也不重置或接管其他工作的改动。
2. 以完整功能为单位列显式白名单并检查依赖闭包，包括运行所需的规则、少量必要 JSON、模板和构建模块；检查凭据、隐私和异常大文件。同步修订局部 ignore，使不应跟踪的生成物不继续干扰审阅；不为推送强制纳入大数据。
3. 9 个删除的 `scripts/release` 旧脚本先与退役及迁移回执逐项核对，明确是否确为已退役实现，再决定提交删除或保留。不能仅凭工作区删除状态认定可删。
4. 以隔离代表路径、导入和构建计划及现行只读验证检查闭包；不重跑全库研究或正式生成器。按完整功能分批提交，提交前逐批核对暂存差异。
5. 代理恢复后先 fetch，核远端分叉和本地提交；常规 push，不 force，之后核远端 SHA。远端仍不可达时保留本地可审阅结果并报告，不能声称推送成功。

GitHub 轻量源码仓库并非被忽略成果的备份；完整结果仍依现行分层发行约定。未跟踪文件的体积不等于应提交的体积，尤其 `projects/reader/site` 大量生成页面及 `docs/project-layout` 的大元数据需明确用途和 ignore 策略。

## 三、清理等级及能力变化

| 等级 | 保留与动作 | 失去的能力或条件 |
|---|---|---|
| L0 | 保持现状，未知或受保护项默认留存 | 不主动获得空间。 |
| L1 | 仅处置精确确认的垃圾、可重建缓存或无消费者测试副本 | 要有具体生产者、消费者、重建输入和路径证据；目录名或年代不足以定级。 |
| L2 | 保留所有不同证据字节；历史载荷经内容去重、压缩并按需恢复 | 旧路径可能不再随时展开可读；需保留路径映射、完整读回验证及恢复样本。恢复不能重造原文件对象 ID，依赖原对象身份的项目另列保留或退役。推荐主线使用。 |
| L3 | 保留当前复现闭包、当前证据和必要报告 | 接受旧周期完整复验和旧字节回滚能力部分丧失；逐项说明影响，适合经核实的废弃展示试验候选。 |
| L4 | 保留成果页面、JSON/CSV、图片和说明 | 接受研究与重建能力损失；与现行完整可复现交付目标冲突，只有用户明确改变目标后才可采用。 |
| L5 | 针对单条明确放弃的支线处置其独占内容 | 不是全库更高等级；先抽出在用输入、依赖和必要来源，再由用户决定精确范围及接受后果。 |

等级表达保留能力，并非自动执行规则。同一路径按一个最终动作和等级归类；跨组共享内容单列消费者。受保护、依赖不明、缺少可靠重建条件的项目先留存，待证据明确后再议。

区分两个目标：停止维护支线能降低复杂度，清理大载荷才能显著释放空间。源码和文档即使数量多，也不应只为省空间优先删除。`.git/` 保留版本历史；`.venv/`、`tools/` 只有在依赖获取与重装条件明确且不影响正在运行的任务时才评估重建。原始采集归档与展开缓存可能互相重复，但必须核来源、解压流程和消费者后才能收敛副本。

## 四、全文件分类与收益核算

形成互斥覆盖的全文件清单，包括受保护和保留项，而非只列删除候选。最少字段：`path`、`branch`、`role`、`size`、`producer`、`consumer`、`rebuild_command`、`input_version`、`unique_evidence`、`current_pins`、`action`、`level`、`survivor`、`hash`、`recovery_cost`、`consequence`、`status`。未知填未知并保留，不能填推测结论。

以同一生产规则的文件组批量归类，再将结果展开到每个路径；人工重点检查唯一输入、固定路径消费者、跨支线共享件及例外，不逐一打开百万份媒体和同构 JSON。复用 11 月 6 日的引用／耦合调查作为线索，补查此后新增代码和当前路径，不把旧静态命中或未命中当作完整依赖证明。内容哈希先限定于实际候选和存活副本，不先做全项目双份哈希。

扫描按文件、链接和目录分别记录，不跟随 junction；父子汇总不叠加，逻辑字节与实际占用分开。候选临执行前重新 lstat，确认路径、链接类型及硬链接关系；核对来源身份、保护状态和同哈希存活件。唯一内容需验证归档及路径映射，已有压缩或硬链接影响净收益，不以逻辑体积冒充可释放空间。

收益先报告经过逐项依赖和存活件核验的范围，明确归档占用和恢复成本；实际执行后记录磁盘可用空间变化。当前 retention/state 的 `RETAINED 12`、`reserved_bytes 8032729057` 是预约状态，不是实际释放量。剩余 5 个 v2 previous 删除后数据收益为 0 B 且损失旧现场身份，优先级低。

## 五、历史教训与实施方法

2026-10-24 误清理遗漏了 `work` 中固定消费者：已恢复 7,980 项，仍有 4,072 项缺件（755 基线 JSON、302 早期 JSON、3,015 HTML），旧字节复验和回滚受限。最新结果无法替代原 SHA，本方案不重新启动恢复。2026-10-26 清理方案的容量估值已过期，不用于当前收益承诺。

C19 的可复用方法是精确清单、同哈希存活件核验、不同内容先归档并全部读回、抽样恢复、微批及后验：当时处理 4,472 载荷，其中 278 个不同内容全部读回，8 个恢复样本通过，实测空间增加 2,585,399,296 B，元数据保留。只能复用方法，不能复用旧名单或授权。

未来执行时，先让用户基于支线选择、等级、能力损失、收益范围和精确白名单作决定；按该决定实施。执行前再次核状态及候选身份，先验证必要归档和恢复，再微批、记录逐项日志、后验消费者与保护项、记录空间回执并更新交接。失败则停在受影响范围，保留诊断；不以本方案自动扩大权限或设立额外大型治理流程。

## 六、实施交付与完成标准

| 阶段 | 交付 | 完成标准 |
|---|---|---|
| 1 Git | 显式提交清单、必要排除项、验证记录、提交 SHA 与推送回执，放 `operations/records/git-sync/<本次版本>/` | 必需源码／配置／数据闭包齐全；未夹带其他任务、原件或大批生成物；本地提交与远端 SHA 对账。网络失败时明确标“本地完成、推送未完成”。 |
| 2 支线取舍 | 八组职责、依赖、当前入口与用户选择表，续写本版方案的后续版本 | 每组明确继续／冻结／放弃，跨组共享输入有人保留；不为分组重做迁移。 |
| 3 全文件分级 | 新版逐文件清单、按支线和等级汇总、精确候选、例外与能力损失表 | 普通路径与链接都有分类；无遗漏／重复计入；未知项留存；收益计算扣除存活件与归档新增量。用户据此决定实际清理范围。 |
| 4 获选清理 | 清理日志、必要恢复样本、消费者后验、实际空间回执、保留与缺口说明 | 仅处置获选白名单；输入和当前正式结果保护通过；归档恢复可用；Git／导航如有变化同步记录。 |

业务代码无变化的阶段不额外造测试。发生写域重叠时先做独立部分；本轮只读文件观察不证明其他聊天已经停工，真正提交或删除前再核实际写入状态。
