## 实现前必须闭合的读写接口

具体逐根脚本、输入输出和验收已分在[解包／媒体](unpack-assets.md)、[研究／阅读器／参考／运维](research-reader-ops.md)。统一实现采用下面的共同契约，避免每棵临时打一套补丁：

- 明确一份版本化旧逻辑根→新物理根配置，并让真实路径打开／写入处和默认CLI共同使用。只改导航或读取端不合格；必须覆盖未来生成输出、latest写入、子进程、CWD、`__file__`和import期根缓存。未搬的raw、work、APK和KEEP根按原契约解析，不套通用前缀替换。
- 保留报告 `json_file`／`original_file`、Unity `text_path`、manifest来源值等冻结字节，由明确消费者解析旧逻辑路径。对archive/work_file、local_path、output_path、root_id/path_kind分别按语义处理；不得把所有字符串替换，也不得丢件后静默回旧output。
- 缓存77份decoded、APK/native恢复链、relocations/seed/symbols保持原SHA／版本拒绝。路径变化不能伪造新数据、放宽NativeDecoder边界或把未声明的本机work文件当新依赖。
- `full_unpack` ledger/shards/coverage、图片绑定、名册、规则证据、reference_pairs／译文和reader URL成组适配。旧HTML／README的跨树相对链接需明确新导航或经批准的只读服务路由；不声称文件搬后旧链接自动有效，更不能为目录整理重写冻结HTML／manifest。仍在KEEP中的主线代码和reader也必须能读到已迁外部输入。
- 明确候选全部读写边界，代表性查询／单样本生成在小型独立输出中验证，核输入身份、答案与路径敏感签名、语义条件和错误路径。无须为整理全量重解码、重建全部主线／reader或复制大型媒体；不能用仅mock通过代替真实消费者验证。
- 对带冻结子项的迁移候选，在最终精确清单中逐项核保护契约；保护不允许迁址时该根不能偷偷进入物理清单。本包的条件候选不是冻结例外授权。

目前16棵解包／媒体根均需适配，研究／参考的生产读写也未实现新根候选；只有两棵运维树已有小范围工具。**总包不标READY，也不提供一个绕过这些闭包的“遍历31根直接Move”脚本。**

## 一次迁移的实际组织方式

是一次组织和维护窗口，内部仍按依赖顺序执行，不是31根原子交换，也不是反复找主持的多个小批。

1. **窗口前独立完成全部准备。** 同一版本的路径适配候选、31根精确文件／目录／reparse身份、完整别名和目标冲突清单、4指针新值、导航差异、恢复方案及Astra验收都闭合。大树只做必要metadata与风险对应的hash，不新增无条件双端全量SHA门槛；仅增量补变化源。
2. **一次主持总交接。** 用[唯一提示词](host-handoff-prompt.md)把全部根、代码、指针、别名、窗口和主线边界一起接走。主持当前没空，不立即打扰；窗口不能借用第二批19:30或第三批30分钟模板，应按最终清单和验证时长另定。
3. **一次用户最终物理授权。** 针对经过实现和候选验收的最终精确根／指针／别名／代码差异申请；本轮方案、主持同意或旧授权均不替代它。全组未准备好就不开始，也不擅自缩成新的两目录小批。
4. **一个新切换窗口。** 相关生成／校验在自然事务完成后让出正在迁移输入的读写；研究、规则讨论和不涉及该写域的工作可以继续。移动生产输入时不能承诺相关生成进程照常使用旧路径。临前核当前使用者、ID／mtime／目标、别名、有效授权与窗口，发现漂移立即暂停。
5. **物理逐根，逻辑统一发布。** 必要局部ignore先落地；每根同E卷rename一次并验真，获准切换的运行junction逐个next验读、formal→previous核旧结构、next→formal验读；保留previous和WAL，不建常驻旧output兼容junction。六个独审入口只按另经明确批准的保护契约处理，不包含在默认重定向操作中。整个依赖组验证完成后才统一发布路径配置、4指针新值与导航，并用正式消费者代表读回。中间状态不供主线生成调用。
6. **一次最终验收。** Astra独核实际根、指针、别名、受保护材料、消费者和链接，执行对话交一份完整成功／失败／暂停／恢复及真实退出码回执，再归还可继续生成的入口。失败不能写成全组完成。

## 空间与工程量

整目录同E卷rename不额外复制既有载荷，不释放被搬的数据；源和目标保留同一文件对象。原APK/raw/work、环境和大媒体不复制；只保存元数据、少量关键前像、候选源码和小样本输出，回执另占小空间。现有计数覆盖一部分根且有时间点，八棵解包／媒体大根没有可靠既有全树体积，本轮明确不补造全量总GB或“半小时一定完成”。

工程量主要在生产读写路径、冻结来源解析、131条旧别名及跨树链接适配，不在搬99KB的两棵运维树。复用同一个路径契约、一次公共代码整合、一次别名清单和一次主线交接，能避免此前小批重复成本。最终切换时长在身份清单及候选验证完成后估算，不预设短窗口让任务搬到一半过期。

## 中断与回退

每步记录INTENT、紧邻状态核验、授权时间检查、实际对象ID与成功／失败退出码。部分树已迁时先保留实际新位置，停止受影响依赖组，默认前向修复；旧指针／路径配置不能指向已经迁空的源。不得整树覆盖、盲重跑或自动“整体回退”。

确需逆搬时，先确认新树内容身份、旧source仍精确缺失、无并发新增及消费者状态，另定具体受控恢复范围，按回执先恢复材料并验真，再处理junction／指针／代码；保留新成果和所有失败证据。窗口过期或关键next回执缺失时，现有第三批小工具不能直接跨窗口续跑，必须重新审定恢复契约。删除previous、空目录、原件、历史证据和Git提交／推送都不在这次迁移默认范围。
