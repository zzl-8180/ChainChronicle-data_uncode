# 一次统一执行的部署与恢复边界

此文是未来执行顺序，不是执行授权或可直接运行的迁移脚本。沿用原统一总账的31根、2顶层指针和4可变selector；不扩大到KEEP、previous、旧空目录或历史删除项。

1. **窗口前**：一次主持交接确认全部接口写域、真实使用者、相关事务终态、六独审入口契约和可观测窗口；独立验收剩余具体代码点／生产事务。重新读取正式源码与根导航，只在批准写域最小重基候选；保留C19/C20及所有并发新增，不追改游戏语义。冻结最终代码、配置、导航、根／alias／指针精确清单与SHA，取得用户针对这份最终范围的物理授权。
2. **临窗**：核源根真实ID、目标不存在、同E卷、祖先及全树内部reparse策略、任务写域／使用者、保护身份和4selector身份。85硬链接源及外部伙伴复核inode、nlink和未写；完整别名清单不得只复用131旧种子。任何新增、冲突、读取错误或授权过期均停止对应组；全组未满足不偷偷缩成另一小批。full_unpack部分元数据不是全树无reparse的证明。
3. **候选合入与物理搬迁**：代码及无激活配置在窗口内按精确补丁合入并验SHA；locator尚不存在时保持旧模式，禁止启动涉及选定输入的生产器。逐根同卷rename，不复制payload、不合并目标，不改冻结子文件。每步先写WAL和原ID／位置，再核新ID与既定内容证据。四selector的定位字段按批准的新版本变化，manifest/build/snapshot身份字段不伪改。
4. **历史入口**：仅对明确获准的运行alias逐个建next并完整验读，formal→previous核结构身份，再next→formal验读。两次rename非原子，不保证零竞态。v3 analysis/provenance后缀保留。六冻结独审入口不套用该步骤，只按最终获准的独立保护契约；提案为保留原对象与target、外部映射读取新址并退役旧直读能力，该提案当前没有授权。
5. **统一发布**：安装locator前的新址聚合、保护及消费者验读，使用显式SHA绑定的暂存配置／受控只读维护入口，不能用仍处legacy模式的默认进程冒充新址验收。通过后安装版本化配置 `operations/config/project-layout/20261108.json`，再受控发布 `scripts/project_layout_active.json`。单个locator替换可用同目录原子replace；多根、多指针及多alias整体不是原子事务。所有长期缓存进程必须在选定窗口退出／重启，否则解析器拒绝进程内切换，不能假设其自动热更新。安装配置后才使用实际状态更新导航，并验真实本地链接／浏览器与必要生产消费者；各阶段实际退出码和失败均留证。
6. **恢复**：未发布时按WAL处理已经移动的根，不能让运行者按旧模式读已迁空的旧根。优先维持已经验真的新位置并完成前向修复；只有证明无新写入／无目标冲突，且恢复材料验真，才可按批准清单逆搬并恢复指针／入口。已发布且出现新写入时，不撤路径适配冒充回退，不把junction指回空旧根，不覆盖新产物。停止相关接口、记录真实位置并重新确定恢复边界。

临时空间是源码／候选、小配置、WAL和回执；同卷整目录rename不产生完整载荷副本。不得以节省空间为名删除失败、原独审、冻结证据、previous或空目录；这些后置动作须另定精确范围和授权。不运行旧打包／恢复／清理、旧冻结verifier或生产全库重建替代维护验证，不自动Git提交或推送。
