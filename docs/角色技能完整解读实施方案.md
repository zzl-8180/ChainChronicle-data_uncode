## 1. 目标与质量底线（不变）

最终要回答：**某个角色的每条技能描述，究竟增加多少攻击、减少多少伤害、提供多少固定防御/暴击/回复，以及持续多久、对谁生效、需要什么条件。** 逐描述、逐效果解析：一条描述可能同时含多项效果，有证据的单项先交付，同句剩余效果始终保留为可追踪待办；确认/类型外推/推断/未知分档，推断不冒充确认；不跨记录合并数值；同号跨命名空间（缓存/APK、普通/Boss）不合并不跨层取值；缺失/null/真实零分别处理，不填零不猜。

整行有答案、出现机制关键词、页面生成成功、A 类晋级、检查器通过，**都不能代替逐效果完成**。「不适用固定数值」须有依据，不能成为未知效果的兜底分类。

## 1.1 工作原则（2026-10-24 用户裁定）

1. **主线优先**：以完成已确认的项目目标为中心（§1 的逐效果数值解读与交付）；流程整改、存储治理、文档完善、历史恢复等附加工作不得挤占主线任务的时间与资源——附加工作只在服务主线或用户明确指令时开展，且不得倒过来成为主线的前置条件。

## 1.3 玩家能看懂的中文表达与验收（2026-10-25 用户要求补充）

**目标**：玩家通过默认阅读层即可理解某项效果“对谁、改变多少、在什么条件下、持续多久、哪些部分还不清楚”。使用游戏中常见的中文表达，数值紧邻对应效果；原文、原值、字段、精确公式和来源保留在可展开的“原文／计算与来源”，不要求玩家先读研究记录。译文、中文改写和排版不计新增数值解析收益。

**表达要求**：
- 已知的数值须带单位或计算基准，保留原效果涉及的对象、条件和持续时间；未知部分就地说明。多对象、多档位按实际来源成组展示，不将不同pattern的数值分别排序后拼接。
- 区分攻击倍率、增加百分比、百分点、固定量、攻击间隔与攻击频率。例如有依据的单项间隔因子0.675可写“这项加成单独生效时，攻击间隔缩短32.5%”，不能写成“攻击速度提高32.5%”；无已证基准不反推增幅。
- 局部伤害公式可写“该段按技能基础攻击的25倍计算”，保留适用档位和“实际扣血尚未验证”等必要边界；基础输入未确认时明确写明。没有调用端时间依据的delta不能改写成秒，尝试次数／生成段数不能改写成保证命中次数。
- 部分解析须直接说明已知与未知，如“停止移动后的额外加成已解析；基础攻击间隔仍未确定”。确认、类型外推、推断、未知用简短文字可辨；不以流畅中文隐藏未知或提升证据等级。
- 批量成果不得只列已解答案：同句未解效果按row_id从正式账本生成默认中文提示，保留effect_id及gap/backlog证据；批次汇总不能替代逐行披露，展示-only不新增语义答案。
- 默认效果说明不使用param、载体、S4、delta、floor/clamp等内部术语充当答案。中文说明逐项对应现有描述／效果／答案及条件；无法唯一对齐时分项列值并说明缺口，不用网站数字补空、不按同数猜来源，也不要求前端自行推导技能语义。

**最小验收**（并入既有§6检查／独立语义审查，不另建审查链）：
1. 选本轮实际涉及的数值、条件分档、部分解析／未知和推断样本；同一例可覆盖多个风险，无需机械凑样本数。审查者只看默认中文，即可复述效果对象、量与基准、适用条件、原文涉及的时长和未解部分；缺少已知要素或把未知读成确定则不通过。此项防止“有数字但玩家读不懂、条件被省略”的实际交付问题。
2. 将上述样本逐项对照正式JSON与来源，核数值、单位、对象、条件、档位成组关系、证据状态及未解项均未改变，且能从说明定位对应原文和计算依据。此项防止润色时变更语义或错配分支；涉及语义变化按§6独立定向核验，纯披露／排版沿用原级别。
3. UI样稿及正式展示接入时，在桌面和窄屏实际查看：正文、数值、必要条件和未解提示可读，来源可点击／键盘展开；如提供复制，复制结果保留必要条件、证据与版本。此项防止折叠、悬停或复制丢掉关键上下文；未实测项目如实注明。

**生效与分工**：本节用于后续新增／修改的玩家说明和展示接入验收，不追改历史批次验收结论，不以全库翻译为解析前置。解析批次提供其新增效果的简明中文说明并核对语义；全站样式／模板改造由用户交给第三方对话独立试做，限定自身预览目录，正式共享生成器和产物仍由主持协调整合。现有页面尚未据本节完成全量改造，不将条文登记写成UI已交付。

## 1.5 主线提速：研究子项、语义批次与交付包（2026-10-29 用户授权，C7-P1 起试行）

**三种单位不得混淆**：
- **研究子项**：一个公式、引用分支、模板或反例的研究/实现单位，可并行。先局部候选生成、来源检查、正反例和独立语义核验，未成熟代码只放候选目录，不进入正式源码签名。
- **实质语义批次**：按共同规则族与风险划分，分别保留收益、词条、检查范围与独立审查结论，仍是每三批一次方向复核的计数单位。
- **交付包**：同一周期内 1—3 个成熟语义批次组成的冻结源码/输入集合及一次正式生成。机器工作共享，批次收益不得合并成一个数字；交付包不得跨越第三批后的停审边界。工程优化与纯登记维护不冒充实质语义批次。

**Y.G. 优先选题（2026-10-29 用户补充，嵌入本节而非另立方案）**：提速只改变处理方法与发布节奏，不改变 Y.G. 主线优先级。每包必须先从 Y.G. 未解效果选题，再判断哪些已有公式、来源清楚、对象与阶段可确定，适合结构推广；不得先从全库挑最易批量的族，再把碰巧涉及 Y.G. 的成果当作优先目标。选题顺序：①Y.G. 中证据充分、可直接补答案的子族；②Y.G. 中只差少量、范围明确的来源或阶段核对子族；③同一已证适用域内可低成本顺带完成的非 Y.G. 记录。G7 与「已有公式且引用唯一」都不是脱离 Y.G. 目标的独立排序理由，允许改选其他更成熟的 Y.G. 规则族；非 Y.G. 连带不得延迟成熟 Y.G. 交付，不为增加全库数量扩大语义域，某族难做不无限深挖。每包任务卡在开工前简写目标 Y.G. 卡／未解效果、选择理由、预期收益类别、非 Y.G. 连带范围及主要障碍；候选数量不是承诺收益，已交付项不得重复计算。若 Y.G. 候选确有证据障碍，只记录具体缺口及已检查的有限候选范围，可继续做直接服务 Y.G. 的必要工程，不悄悄转为非 Y.G. 主导；实质改变主线优先级须交用户决定，不凭空承诺每包都有 Y.G. 新增。收官除既有收益分类外，分别列 Y.G. 新增已答效果／未解净变化／完整描述增量、非 Y.G. 连带收益和工程耗时改善；扫描量、规则登记数、普通角色新增量与工程提速均不得冒充 Y.G. 解析进展，只有 Y.G. 净增量与有效耗时同时记录时才评价单位时间产出。

**推荐流水线**：按族扫描并分配研究子项 → 各子项局部实现、样本、正反例 → 各语义批次独立核验 → 主持合并成熟批次并做共同路径交互检查 → 冻结输入/源码/规则/受影响卡集/预期变化/审查覆盖/容量检查 → **每包一次**正式全库重建 → 账本 → 入口/选题链 → 固定全套机器检查、各批最终语义核对与合并差异核对 → 统一收官。冻结前只写「候选审查通过，待正式交付」，正式产物核对后才写最终通过。合并等待建议不超过一次主持工作时段、最多 2 小时，但不以凑满三批为交付前提；未解决来源歧义、新原生或跨层风险的子项移出本包，不拖住成熟部分。

**性能执行约束（2026-10-29 补充）**：在本次已验证环境和实现下，后续沿用 jobs 4；环境、并行实现或负载没有实质变化时，不重复 jobs 1/2/4 三档全库基准。C7-P1 正式全库生成 1 次，另有 3 次全库性能试跑，合计 632 秒。27.79GB→1.64GB 是逻辑读取量；8.26×/8.79× 仅指本组账本测试，不代表整个项目加速。实际资源不足时仍沿用既有降档措施（按实测内存/CPU/磁盘降 jobs，MemoryError 或子进程崩溃时串行重建失败卡），不得为保持 jobs 4 而突破资源与容量边界。

**检查可以共享、不得取消**：同一冻结版本的基线、全库生成及固定机器检查按包共享，不要求每个小子项或参与方机械重复；原值/单位/对象/条件/阶段、来源解引用、正反例、独立语义审查、旧答案与保护项、页面/账本/入口/选题一致性仍必查。同一问题的独立审查上下文可连续核多个同族批次，但逐批保留结论；实际修改或新疑点只补受影响检查。冻结版本未变就不重复研究或重跑已通过检查，禁止改写 receipt、伪造统一签名、取消来源/哈希检查或混用版本。真正增量生成仅在计时证明值得投入后另行立项，先验证依赖失效、复用签名与恢复方式，未通过前仍按本包一次全库重建。

## 1.6 机制优先研究与批量逐卡核验（2026-11-04 起）

**默认方法**：在§1.5的Y.G.优先选题之后，先按机制族建立一次共用判据，再批量逐卡核验。机制族按源层、命名空间/表、类型及实际消费路径、对象/阶段/条件划分；同名字段、相似原文或同号ID不能自动归为同一适用域。已有已确认公式直接复用，只研究本轮缺失的绑定或条件证据；共同消费者证据欠缺时，先做有界研究并登记缺口，不让多名代理逐卡重复遇阻。

**执行顺序**：固定当前未解基线与版本 → 整理机制卡（公式/单位/条件/允许域/中性与缺失语义/反例/未知）→ 核代表样本及本族真实边界 → 批量解引用并逐效果出候选 → 冻结与既有例行独审 → 主持整合成熟项，接回§1.5/§5/§6的每包一次正式生成与交付。机制卡和清单可合并在任务目录，不另造逐卡长报告；索引和同版本成功结果可复用，输入、规则或绑定判据变化时仅复核受影响项。

**批量不降低逐卡标准**：每项保留cid/row_id/effect_id、原文、快照、源层/表/记录/字段及定位、原值、换算与单位、对象/条件/档位、数值证据、关联证据、审查引用和未解项。沿真实角色引用→父记录→载体→字段核对，不按同文或ID规律复制；检查完整父文、竞争载体、邻句与条件增强。直接父与唯一sub按实际形状和下标解引用，不假设`sub[0]`，父与sub同类载体并存时不得任选；句面／fragment／source span消歧，已有答案行不重复追加。缺失/null/零/中性值分开，有证单项可交付，剩余效果可追踪。

**同族实现与审查分工**：优先共用解析器和冻结身份清单，不为每张卡复制模板。确定性脚本负责大范围扫描、计数、差异和机器验收；模型负责实现与独立语义审查，审查须从原记录独立重导而非只调用被审解析器。批次顶部计数、公式确认和页面生成均不等于逐效果归属确认。
